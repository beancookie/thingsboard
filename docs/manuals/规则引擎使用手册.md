## 2. 规则引擎是什么

规则引擎用于处理平台中的消息流。设备上报的遥测、属性、RPC、连接状态等消息都会进入规则引擎，由规则链决定如何处理。

### 2.1 核心概念

| 概念 | 说明 |
| --- | --- |
| 规则链 | 由多个规则节点和连接关系组成的处理流程 |
| 规则节点 | 规则链中的一个处理步骤，例如过滤、转换、保存、告警、RPC |
| 消息 | 在规则链中流转的数据，包含消息体、元数据、消息类型和消息来源 |
| 消息来源 | 消息来源实体，通常是设备，也可以是资产、租户、客户等 |
| 元数据 | 消息元数据，例如设备名称、设备类型、消息时间戳 |
| 连接 | 节点之间的连线，带有 `Success`、`Failure`、`True`、`False` 等标签 |
| 根规则链 | 处理所有传入传输消息的默认规则链，只有一个 |
| 调试模式 | 记录消息在规则链和节点中的流转情况，用于排障 |

### 2.2 消息流转

```text
设备上报
  -> 根规则链或产品配置绑定的规则链
  -> 消息类型判断
  -> 数据校验 / 转换 / 补充
  -> 保存遥测或属性
  -> 告警 / RPC / Kafka / MQTT / REST API
```

### 2.3 根规则链、产品配置规则链和嵌套规则链

| 类型 | 说明 |
| --- | --- |
| 根规则链 | 平台默认入口，处理未绑定其他规则链的设备消息 |
| 产品配置规则链 | 绑定在产品配置上，优先级高于根规则链 |
| 嵌套规则链 | 被规则链节点调用的子规则链，用于拆分复杂逻辑 |

产品发布时，平台会把产品规则链绑定到对应产品配置，因此产品设备通常不走根规则链。

## 4. 创建与导入规则链

### 4.1 创建规则链

1. 在「规则引擎」页面点击「创建新规则引擎」。
2. 填写规则链名称，例如 `场景联动规则链`。
3. 可选开启「调试模式」。
4. 填写描述。
5. 点击保存。
6. 进入规则链编辑器添加节点。

> 截图占位：`images/rulechains/03-create-rulechain.png`

字段说明：

| 字段 | 必填 | 说明 |
| --- | --- | --- |
| 名称 | 是 | 规则链名称 |
| 调试模式 | 否 | 记录规则链调试事件，生产环境建议关闭 |
| 描述 | 否 | 规则链用途说明 |

### 4.2 导入规则链

1. 在列表点击「导入」。
2. 选择规则链 JSON 文件。
3. 平台打开规则链编辑器并加载导入内容。
4. 检查节点、连接和配置。
5. 点击保存。

导入的规则链可能包含设备 ID、客户 ID或外部系统地址，导入后需要逐项检查。

### 4.3 导出规则链

在规则链列表或详情页点击「导出」，平台会下载规则链 JSON 文件。

导出文件可用于备份、迁移和版本管理。导出前确认规则链已保存。

> 截图占位：`images/rulechains/13-import-export.png`

### 4.4 设为根规则链

1. 在规则链列表选择一条非根规则链。
2. 点击「设为根规则引擎」。
3. 确认后，该规则链将处理所有未绑定其他规则链的传入消息。

注意：

- 根规则链影响范围很大，变更前请在测试环境验证。
- 原根规则链会变成普通规则链。
- 根规则链不可删除。

> 截图占位：`images/rulechains/12-set-root.png`

### 4.5 嵌套规则链

在规则链编辑器中可以通过上下文菜单创建嵌套规则链，并用规则链节点调用。

适用场景：

- 把不同产品、不同区域的逻辑拆开。
- 复用告警、通知、数据清洗流程。
- 降低单条规则链的复杂度。

## 6. 常用节点

### 6.1 过滤类

| 节点 | 用途 |
| --- | --- |
| `message type switch` | 按消息类型分流，例如遥测、属性、RPC |
| `message type filter` | 只允许指定消息类型通过 |
| `script` | 使用脚本返回布尔值过滤消息 |
| `switch` | 使用脚本返回自定义标签，实现多路分支 |
| `entity type switch` | 按消息来源实体类型分流 |
| `device profile switch` | 按产品配置分流 |
| `asset profile switch` | 按资产配置分流 |

## 7. 典型流程

### 7.1 遥测校验、存储和转发

产品规则链通常包含：

```text
Message Type Switch
  -> Post telemetry
  -> 获取 TSL 属性
  -> 校验遥测
  -> Save Timeseries
  -> Kafka / 其他输出
```

具体产品规则链说明见 [产品与规则链](../04-产品与规则链.md)。

### 7.2 温度超限告警

```text
设备遥测
  -> message type switch
  -> script / filter（temperature > 80）
  -> create alarm
  -> 通知节点
```

恢复正常后：

```text
设备遥测
  -> filter（temperature <= 80）
  -> clear alarm
```

告警查看、确认、清除和通知配置见 [告警与通知使用手册](告警与通知使用手册.md)。

配置要点：

- 告警类型和严重级别要统一。
- 告警详情建议包含设备名称、阈值和当前值。
- 清除告警条件要明确，避免告警长期不关闭。
- 告警节点输出有 `Created`、`Updated`、`False` 等标签，可按标签继续处理。

### 7.3 多设备场景联动

规则引擎可以实现跨设备联动，但平台没有独立的「场景」实体，需要用规则链组合实现。

#### 示例：人体感应开灯

设备：

- `motion-01`：上报 `{"motion": true}`
- `light-01`：支持 RPC 方法 `setState`

建立关系：

```text
motion-01 --Controls--> light-01
```

规则链：

```text
motion-01 遥测
  -> message type switch（Post telemetry）
  -> script（判断 motion）
  -> filter（motion === true）
  -> change originator
       source: Related Entity
       relation: Controls
       direction: FROM
  -> script
       payload:
       {
         "method": "setState",
         "params": { "state": "ON" }
       }
  -> rpc call request（timeout 10s）
       Success -> log / save time series
       Failure -> create alarm / send notification
```

关键点：

- `rpc call request` 默认发给消息来源，不是任意设备。
- 必须先用 `change originator` 把消息来源切换到目标设备。
- 目标设备必须在线并支持 RPC。
- MQTT 设备通常需要订阅 `v1/devices/me/rpc/request/+`，并回复 `v1/devices/me/rpc/response/{requestId}`。

> 截图占位：`images/rulechains/14-scene-linkage.png`
>
> 截图占位：`images/rulechains/15-rpc-config.png`

#### 示例：有人且光照低才开灯

```text
motion-01 遥测 motion=true
  -> change originator 到 light-sensor-01
  -> originator telemetry 读取 illuminance
  -> change originator 到 light-01
  -> script 判断 metadata.illuminance < 100
  -> script 生成 method/params
  -> rpc call request
```

如果设备之间已有关系，也可以用 `related entity data` 读取关联设备的最新遥测，再用 `change originator` 切换到执行设备。

#### 场景联动注意事项

- 目标设备离线时 RPC 会失败，需要配置失败分支。
- 避免 A 控制 B、B 又控制 A 形成循环触发。
- 使用 `deduplication` 或业务状态字段做防抖。
- 规则引擎单条消息是无状态的，场景状态建议保存在设备/资产属性、告警或独立状态实体中。
- 复杂场景建议单独建场景规则链，不要直接修改所有产品共用的规则链。
- 目标设备不支持 RPC 时，可以使用 `mqtt`、`rest api call` 或 `kafka` 节点对接外部系统。

### 7.4 对接外部系统

常用方式：

- `rest api call`：把数据推送到业务系统。
- `mqtt`：发布到第三方 MQTT 消息代理。
- `kafka`：写入 Kafka 主题。
- `send notification` / `send email` / `send sms`：发送告警通知。
- `AI request`：调用 AI 模型做分析或决策。

外部节点需要配置地址、认证、超时和重试策略，生产环境建议配合监控和失败告警使用。

## 8. 调试与验证

### 8.1 开启调试模式

1. 打开规则链详情或编辑器。
2. 勾选「调试模式」。
3. 保存规则链。
4. 在规则链详情「事件」页签查看 `DEBUG_RULE_CHAIN` 事件。
5. 在节点详情「事件」页签查看 `DEBUG_RULE_NODE` 事件。

调试模式会产生额外事件，生产环境使用后请关闭。

> 截图占位：`images/rulechains/09-debug-mode.png`
>
> 截图占位：`images/rulechains/10-debug-events.png`

### 8.2 节点调试设置

1. 双击节点打开详情。
2. 展开调试设置。
3. 选择记录所有消息、仅记录失败消息或设置调试有效期。
4. 保存规则链。
5. 在节点事件页签查看消息进入和离开情况。

### 8.3 脚本测试

带脚本的节点支持「测试脚本」：

1. 打开节点详情。
2. 点击测试脚本按钮。
3. 输入消息体、元数据和消息类型。
4. 查看脚本返回结果。
5. 确认无误后保存规则链。

### 8.4 验证建议

- 先用 `generator` 节点生成测试消息。
- 在关键分支加 `log` 节点，确认消息是否到达。
- 检查消息类型、消息来源、元数据是否符合预期。
- 检查节点连线标签是否选对。
- 检查规则链是否已绑定到目标产品配置或设为根规则链。
- 检查规则链是否已保存，未保存的修改不会生效。

## 9. 绑定、发布与版本

### 9.1 根规则链

根规则链处理所有未绑定其他规则链的传入消息。修改根规则链会影响整个租户的默认消息处理。

### 9.2 绑定产品配置

在产品配置中设置默认规则链后，该类型设备的消息会进入指定规则链。

产品发布会自动把产品规则链绑定到产品配置，具体行为见 [产品与规则链](../04-产品与规则链.md)。

### 9.3 嵌套规则链

使用规则链节点调用子规则链。子规则链通过 `output` 节点返回结果。

适合把场景联动、告警处理、通知发送等逻辑拆分复用。

### 9.4 边缘规则链

边缘规则链在边缘管理页面维护，可分配到边缘实例。云端规则链和边缘规则链不要混用。

### 9.5 版本控制

规则链支持版本历史：

- 编辑器右上角版本控制按钮。
- 规则链详情「版本控制」页签。
- 可以查看历史版本并恢复。

恢复版本前确认当前修改已保存或不再需要。

## 11. 常见问题

| 问题 | 排查 |
| --- | --- |
| 设备消息没有进入规则链 | 检查根规则链、产品配置默认规则链和规则链是否已保存 |
| 节点没有收到消息 | 检查上游连线标签、过滤条件和消息类型 |
| 节点显示红色错误 | 打开节点详情查看配置错误，修正后保存 |
| 保存失败 | 检查节点配置是否完整、是否存在命名冲突、是否被其他人修改 |
| 无法删除规则链 | 根规则链不能删除，先设置其他规则链为根 |
| RPC 没有发到目标设备 | 检查是否先执行 `change originator`，目标设备是否在线 |
| RPC 超时 | 检查设备是否订阅 RPC 主题、网络是否正常、超时是否过短 |
| 告警没有创建 | 检查过滤条件、告警类型、严重级别和 `create alarm` 配置 |
| 告警没有清除 | 检查 `clear alarm` 条件和连线标签 |
| 调试事件没有记录 | 检查规则链调试模式、节点调试设置和调试有效期 |
| 场景联动反复触发 | 增加去重、防抖或状态判断，避免循环控制 |
| 规则链修改后不生效 | 确认已点击保存，并检查设备实际绑定的规则链 |
| 导入规则链后节点异常 | 检查导入文件中的设备 ID、客户 ID和外部地址是否属于当前环境 |
