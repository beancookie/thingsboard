> 中国中铁物联网平台文档集
>
> 适用对象：租户管理员、运维人员、客户用户、第三方接入方

## 1. 文档说明

### 1.1 适用对象

- 平台租户管理员
- 设备接入和运维人员
- 客户用户
- 需要配置告警和通知的第三方接入方

### 1.2 权限要求

- 告警中心对租户管理员和客户用户开放。
- 告警规则仅租户管理员可管理。
- 通知收件箱对所有登录用户开放。
- 已发送、收件人组、通知模板和通知规则由租户管理员或系统管理员管理。
- 通知设置中的短信服务商和移动端配置仅系统管理员可维护。
- 客户用户只能看到分配给本客户或公开的告警和资源。

### 1.3 前置条件

- 已有设备、资产或其他实体产生遥测数据。
- 设备或资产已绑定产品配置或资产配置。
- 如需发送邮件、短信、Slack 或 Microsoft Teams 通知，相关发送方式已在通知设置中配置。
- 如需基于告警自动发送通知，需要先准备通知模板和通知规则。

## 2. 告警与通知概念

### 2.1 告警

告警表示某个实体在一段时间内处于异常状态。告警由规则链中的告警节点或告警规则创建，包含：

- 告警来源
- 告警类型
- 告警级别
- 告警状态
- 开始时间、确认时间、清除时间
- 处理人
- 附加信息和评论

### 2.2 告警生命周期

| 状态 | 说明 |
| --- | --- |
| 活动未确认 | 告警正在发生，尚未确认 |
| 活动已确认 | 告警正在发生，已有人确认 |
| 已清除未确认 | 告警已恢复，但尚未确认 |
| 已清除已确认 | 告警已恢复并已确认 |

### 2.3 告警级别

| 级别 | 说明 |
| --- | --- |
| 严重 | 需要立即处理 |
| 主要 | 影响较大，需要尽快处理 |
| 次要 | 影响有限，按计划处理 |
| 警告 | 需要关注 |
| 不确定 | 无法确定级别 |

### 2.4 通知

通知用于把告警、设备状态、实体变更等信息发送给指定人员或群组。

通知包含：

- 通知类型
- 通知模板
- 收件人组
- 发送方式
- 发送状态
- 已读/未读状态

### 2.5 关系示意

```text
遥测/事件
  -> 规则链告警节点或告警规则
  -> 生成告警
  -> 通知规则匹配
  -> 按通知模板生成消息
  -> 发送到收件人组
  -> 站内收件箱 / 邮件 / 短信 / Slack / Microsoft Teams / 移动端
```

## 3. 告警中心

### 3.1 页面入口

1. 登录平台。
2. 左侧菜单选择「告警」。
3. 进入「告警列表」。
4. 或直接访问：

```text
/alarms/alarms
```

### 3.2 告警列表

列表字段：

| 字段 | 说明 |
| --- | --- |
| 创建时间 | 告警创建时间 |
| 来源 | 产生告警的设备、资产或其他实体 |
| 类型 | 告警类型 |
| 级别 | 严重、主要、次要、警告、不确定 |
| 处理人 | 当前指派的处理人 |
| 状态 | 活动未确认、活动已确认、已清除未确认、已清除已确认 |

常用过滤条件：

- 告警状态
- 告警级别
- 告警类型
- 时间范围
- 来源实体

> 截图占位：`images/alarms/02-alarm-list.png`
>
> 截图占位：`images/alarms/03-alarm-filter.png`

### 3.3 单条告警操作

- 查看详情
- 确认告警
- 清除告警
- 指派处理人
- 取消指派
- 删除告警

### 3.4 批量操作

选中多条告警后可以：

- 批量确认
- 批量清除
- 批量删除

批量操作前请确认选择的告警范围。

### 3.5 告警详情

告警详情包含：

- 来源
- 级别
- 开始时间
- 持续时长
- 类型
- 状态
- 附加信息
- 处理人
- 评论

详情页支持：

- 确认告警
- 清除告警
- 指派或重新指派处理人
- 添加评论
- 查看系统评论

> 截图占位：`images/alarms/04-alarm-details.png`
>
> 截图占位：`images/alarms/05-alarm-comments.png`

### 3.6 指派告警

1. 在告警列表点击处理人列。
2. 选择处理人。
3. 保存后告警会记录指派时间。
4. 可以在详情页取消指派或重新指派。

> 截图占位：`images/alarms/06-assign-alarm.png`

### 3.7 权限说明

- 租户管理员可以查看和处理全部告警。
- 客户用户只能查看本客户或公开的告警。
- 客户用户可以确认和清除本客户的告警。
- 客户用户不能管理告警规则。

```text

```

### 4.2 告警规则列表

列表字段：

| 字段 | 说明 |
| --- | --- |
| 创建时间 | 规则创建时间 |
| 告警类型 | 规则对应的告警类型 |
| 实体类型 | 规则作用的实体类型 |
| 实体 | 规则作用的实体 |
| 告警级别 | 规则会创建的告警级别 |
| 已配置清除 | 是否配置清除条件 |

操作：

- 创建告警规则
- 导入告警规则
- 从 IoT Hub 添加
- 复制告警规则
- 导出告警规则
- 查看事件
- 调试
- 编辑
- 删除

> 截图占位：`images/alarms/07-alarm-rules-list.png`

### 4.3 创建告警规则

1. 点击「创建告警规则」。
2. 填写告警类型。
3. 选择作用实体。
4. 配置参数。
5. 配置创建条件。
6. 可选配置清除条件。
7. 可选配置传播告警。
8. 保存规则。

> 截图占位：`images/alarms/08-alarm-rule-dialog.png`

字段说明：

| 字段 | 说明 |
| --- | --- |
| 告警类型 | 告警名称，同类型告警会归并 |
| 作用实体 | 设备、资产或其他实体 |
| 参数 | 规则计算所需的参数 |
| 创建条件 | 满足条件时创建或更新告警 |
| 清除条件 | 满足条件时清除告警 |
| 传播告警 | 是否把告警传播到关联实体、所有者或租户 |
| 调试设置 | 记录规则执行情况 |

### 4.4 告警规则调试

1. 打开告警规则。
2. 开启调试设置。
3. 保存规则。
4. 在「事件」中查看调试事件。
5. 使用测试脚本验证条件。
6. 调试完成后关闭调试，避免产生过多事件。

> 截图占位：`images/alarms/09-alarm-rule-debug.png`

### 4.5 告警规则 API

| 方法 | 地址 | 用途 |
| --- | --- | --- |
| GET | `/api/alarm/rules?pageSize=100&page=0` | 查询告警规则 |
| GET | `/api/alarm/rules/{entityType}/{entityId}` | 查询实体告警规则 |
| GET | `/api/alarm/rule/{alarmRuleId}` | 查询告警规则详情 |
| POST | `/api/alarm/rule` | 创建或更新告警规则 |
| DELETE | `/api/alarm/rule/{alarmRuleId}` | 删除告警规则 |
| POST | `/api/alarm/rule/testScript` | 测试告警规则脚本 |
| GET | `/api/alarm/rule/{alarmRuleId}/debug` | 查询最近调试事件 |
| GET | `/api/alarm/rules/names` | 查询告警规则名称 |

## 6. 发送通知

### 6.1 页面操作

1. 在通知中心点击「发送通知」。
2. 选择「从空白开始」或「使用模板」。
3. 选择收件人组。
4. 选择发送方式。
5. 填写或确认通知内容。
6. 可选设置定时发送。
7. 预览收件人数和消息内容。
8. 点击发送。

> 截图占位：`images/notifications/04-send-notification.png`

### 6.2 发送方式

| 方式 | 说明 |
| --- | --- |
| 站内 | 发送到平台通知收件箱 |
| 移动端 | 通过移动应用推送 |
| 短信 | 通过短信服务商发送 |
| 邮件 | 通过平台邮件服务发送 |
| Slack | 发送到 Slack 频道或私聊 |
| Microsoft Teams | 发送到 Teams 频道 |

只有已在通知设置中配置并启用的发送方式才可用。

### 6.3 定时发送

1. 打开「稍后发送」。
2. 选择时区。
3. 选择发送时间。
4. 发送记录状态会显示为已计划。
5. 到时间后平台自动发送。

### 6.4 发送预览

发送前可以查看：

- 收件人总数
- 按收件人组统计的人数
- 收件人预览
- 站内、移动端、短信、邮件、Slack、Microsoft Teams 内容预览

### 6.5 通知请求 API

| 方法 | 地址 | 用途 |
| --- | --- | --- |
| POST | `/api/notification/request` | 创建或发送通知请求 |
| POST | `/api/notification/request/preview` | 预览通知请求 |
| GET | `/api/notification/deliveryMethods` | 查询可用发送方式 |

## 11. 权限与最佳实践

- 告警级别要统一，避免同一类问题使用不同级别。
- 告警规则要配置清除条件，避免告警长期不关闭。
- 通知规则要先启用再测试，避免漏发。
- 重要告警使用升级链，按时间逐级通知。
- 发送通知前先预览收件人和内容。
- 定期检查发送失败记录和通知设置。
- 生产环境不要长期开启告警规则调试。
- 客户用户只应看到本客户或公开告警。
- 不要给无关人员配置高优先级告警通知。
- 定期清理历史通知和无效收件人组。

## 12. 常见问题

| 问题 | 排查 |
| --- | --- |
| 告警没有生成 | 检查遥测数据、告警规则、规则链告警节点和产品配置规则链 |
| 告警没有自动清除 | 检查告警规则是否配置清除条件 |
| 告警级别不正确 | 检查告警规则的创建条件和级别配置 |
| 收不到通知 | 检查通知规则是否启用、模板和收件人组是否正确 |
| 只有站内通知 | 检查邮件、短信、Slack、Teams 是否在通知设置中启用 |
| 邮件发送失败 | 检查平台邮件服务和邮箱配置 |
| 短信发送失败 | 检查短信服务商配置和余额 |
| Slack 发送失败 | 检查 Slack 机器人令牌 和频道权限 |
| Microsoft Teams 发送失败 | 检查 Webhook 或 Workflow URL 和频道配置 |
| 通知重复发送 | 检查通知规则触发条件和升级链 |
| 未读数不更新 | 刷新页面，检查通知状态和未读过滤条件 |
| 客户用户看不到告警 | 检查告警来源是否分配给该客户或设为公开 |
| 客户用户不能管理告警规则 | 告警规则仅租户管理员可管理 |
| 客户用户不能管理通知规则 | 通知规则由租户管理员或系统管理员管理 |
