# 物模型定义规范使用手册

> 中国中铁物联网平台文档集
>
> 适用对象：产品经理、物模型设计人员、第三方接入方、测试与运维人员

## 1. 文档说明

### 1.1 目的

本手册说明中国中铁物联网平台物模型文件的定义规范，包括：

- 物模型文件结构；
- 属性、事件、行为的定义方式；
- 数据类型、范围、枚举和结构体规则；
- 与物联网开发平台物模型文件的兼容说明；
- 导入、保存时的校验要求；
- 运行时字段约定和常见问题。

### 1.2 适用范围

本手册适用于：

- 在“产品管理”中创建或导入物模型；
- 从物联网开发平台导入物模型文件；
- 设计设备上报的属性和事件；
- 设计平台下发的行为；
- 排查物模型导入失败、校验失败和保存失败问题。

### 1.3 术语

| 术语 | 说明 |
| --- | --- |
| 物模型 | 对设备属性、事件和行为的形式化描述 |
| TSL | 物模型文件的 JSON 表达 |
| 属性 | 设备可上报或可配置的数据，例如温度、状态 |
| 事件 | 设备在特定条件下产生的记录，例如告警、故障 |
| 行为 | 平台向设备发起的操作，例如设置模式、复位 |
| 物联网开发平台物模型 | 物联网开发平台导出的旧版物模型文件 |

## 2. 物模型文件结构

### 2.1 顶层结构

物模型文件必须是一个 JSON 对象，顶层字段如下：

| 字段 | 必填 | 类型 | 说明 |
| --- | --- | --- | --- |
| `version` | 是 | string | 物模型版本，长度 1~32 字符 |
| `profile` | 是 | object | 产品信息，至少包含产品 ID |
| `properties` | 是 | array | 属性数组，可以为空数组 |
| `events` | 否 | array | 事件数组 |
| `actions` | 否 | array | 行为数组 |

### 2.2 profile

`profile` 支持以下字段：

| 字段 | 必填 | 说明 |
| --- | --- | --- |
| `ProductId` | 二选一 | 产品 ID，长度 1~64 字符 |
| `productId` | 二选一 | `ProductId` 的兼容写法 |
| `CategoryId` | 否 | 分类 ID，字符串或数字 |
| `categoryId` | 否 | `CategoryId` 的兼容写法 |

`ProductId` 或 `productId` 至少填写一个。

### 2.3 最小物模型

```json
{
  "version": "1.0",
  "profile": {
    "ProductId": "9HYN9PJNOY",
    "CategoryId": "1"
  },
  "properties": [
    {
      "id": "rssi",
      "name": "信号强度",
      "mode": "r",
      "define": {
        "type": "int",
        "min": -120,
        "max": 0,
        "unit": "dBm"
      }
    }
  ]
}
```

### 2.4 标准示例物模型

本手册统一使用以下标准示例物模型：

[standard-thing-model.tsl.json](examples/standard-thing-model.tsl.json)

示例模型摘要：

| 分类 | 内容 |
| --- | --- |
| 产品 ID | `DEMO_TSL_001` |
| 属性 | `temperature`、`humidity`、`mode`、`reportInterval`、`alarmThreshold`、`relay`、`deviceInfo` |
| 事件 | `overTemperature`、`deviceFault` |
| 行为 | `setMode`、`setRelay`、`applyConfig` |

示例模型包含 7 个属性、2 个事件、3 个行为。后续属性、事件和行为示例均基于该模型。

## 3. 命名和数量限制

### 3.1 标识符规则

属性、事件、行为、参数的 `id` 必须满足：

```text
^[A-Za-z_][A-Za-z0-9_]{0,49}$
```

即：

- 以英文字母或下划线开头；
- 只能包含英文字母、数字和下划线；
- 最大长度 50 个字符。

建议使用小驼峰或下划线风格，例如：

```text
temperature
temperature_f
deviceInfo
set_mode
```

### 3.2 唯一性

- 属性 `id` 在同一物模型内唯一；
- 事件 `id` 在同一物模型内唯一；
- 行为 `id` 在同一物模型内唯一；
- 同一事件或行为的参数 `id` 在各自参数列表内唯一。

不同类别之间可以同名。例如属性 `temperature` 和事件参数 `temperature` 可以同时存在。

### 3.3 功能点上限

属性数 + 事件数 + 行为数不能超过 100。

### 3.4 保留字段

属性 `id` 不建议使用以下平台保留字段：

```text
ts
event_id
event_type
event_ts
```

使用后平台会给出提示。保留字段可能与运行时数据冲突，建议改名。

## 4. 属性定义

### 4.1 属性字段

| 字段 | 必填 | 类型 | 说明 |
| --- | --- | --- | --- |
| `id` | 是 | string | 标识符，同时作为遥测键 |
| `name` | 是 | string | 中文名，1~128 字符 |
| `desc` | 否 | string | 描述，最多 512 字符 |
| `mode` | 是 | string | `r` 或 `rw` |
| `required` | 否 | boolean | 运行时是否要求上报，默认 `false` |
| `define` | 是 | object | 数据类型和元数据 |
| `mapping` | 否 | object/array | 枚举映射，兼容旧格式 |

### 4.2 mode

| 值 | 含义 |
| --- | --- |
| `r` | 只读，设备上报 |
| `rw` | 可读可写，可用于下行配置或行为 |

`mode` 必须显式填写。

### 4.3 required

`required=true` 表示该属性在运行时应上报。平台当前主要用于目录展示和后续扩展，不会因为缺失该属性而直接拒绝整条遥测。

### 4.4 属性级 mapping

属性级 `mapping` 用于兼容旧格式。新物模型建议把枚举映射统一写在 `define.mapping` 中。

## 5. 数据类型

### 5.1 类型总表

| 类型 | 运行时要求 | 说明 |
| --- | --- | --- |
| `bool` | boolean 或 0/1 | 规则链归一为 boolean |
| `int` | 32 位整数 | 超出 32 位范围会校验失败 |
| `float` | 有限数字 | 不强制整数 |
| `string` | 字符串 | 长度受字段限制 |
| `enum` | 整数且在映射内 | 映射键必须是数字 |
| `enum_string` | 字符串且在映射内 | 映射保留字符串键 |
| `timestamp` | 整数 | 小于 `1e12` 时按秒处理并乘 1000 |
| `struct` | JSON 对象 | 不支持嵌套结构体 |

### 5.2 define 字段

| 字段 | 适用类型 | 说明 |
| --- | --- | --- |
| `type` | 全部 | 必填，数据类型 |
| `min` | 数值类型 | 最小值 |
| `max` | 数值类型 | 最大值 |
| `start` | 数值类型 | 初始值/建议值 |
| `step` | 数值类型 | 步长，不能为负数 |
| `unit` | 全部 | 单位，最多 32 字符 |
| `mapping` | `enum` / `enum_string` | 枚举映射 |
| `specs` | `struct` | 结构体字段定义 |
| `fields` | `struct` | `specs` 的兼容写法 |

`min`、`max`、`start`、`step` 可以写成数字，也可以写成数字字符串。

### 5.3 数值范围规则

- `min` 不能大于 `max`；
- `start` 必须在 `min` 和 `max` 之间；
- `step` 不能为负数；
- `int` 的 `min`、`max`、`start` 必须在 32 位有符号整数范围内；
- 非数值类型不建议配置 `min`、`max`、`start`、`step`，否则平台会给出提示。

32 位有符号整数范围：

```text
-2147483648 ~ 2147483647
```

### 5.4 枚举

`enum`：

- 运行时值是整数；
- `mapping` 至少 2 项；
- `mapping` 的键必须是数字。

```json
{
  "id": "status",
  "name": "状态",
  "mode": "r",
  "define": {
    "type": "enum",
    "mapping": {
      "0": "停止",
      "1": "运行",
      "2": "故障"
    }
  }
}
```

`enum_string`：

- 运行时值是字符串；
- `mapping` 至少 2 项；
- 映射键可以是字符串。

```json
{
  "id": "mode",
  "name": "模式",
  "mode": "rw",
  "define": {
    "type": "enum_string",
    "mapping": {
      "auto": "自动",
      "manual": "手动"
    }
  }
}
```

`mapping` 也支持数组形式：

```json
{
  "type": "enum",
  "mapping": [
    { "key": 0, "value": "停止" },
    { "key": 1, "value": "运行" }
  ]
}
```

### 5.5 timestamp

`timestamp` 使用整数表示时间：

- 值小于 `1e12` 时按秒处理，并乘以 1000 转成毫秒；
- 值大于等于 `1e12` 时按毫秒处理。

建议统一使用毫秒时间戳。

### 5.6 struct

结构体用于表达一个 JSON 对象属性。

规则：

- `specs` 或 `fields` 不能为空；
- 字段可以是对象形式或数组形式；
- 结构体字段不允许再次使用 `struct`；
- 事件参数不允许使用 `struct`；
- 行为参数当前可以使用结构体，但仍需满足结构体自身规则；
- 运行时只校验“是否为对象且不嵌套”，不校验内部字段类型。

对象形式：

```json
{
  "id": "deviceInfo",
  "name": "设备信息",
  "mode": "r",
  "define": {
    "type": "struct",
    "specs": {
      "vendor": {
        "name": "厂商",
        "type": "string"
      },
      "model": {
        "name": "型号",
        "type": "string"
      }
    }
  }
}
```

数组形式：

```json
{
  "id": "deviceInfo",
  "name": "设备信息",
  "mode": "r",
  "define": {
    "type": "struct",
    "fields": [
      {
        "id": "vendor",
        "name": "厂商",
        "type": "string"
      },
      {
        "id": "model",
        "name": "型号",
        "type": "string"
      }
    ]
  }
}
```

### 5.7 类型示例

布尔：

```json
{
  "id": "relay",
  "name": "继电器",
  "mode": "rw",
  "define": {
    "type": "bool"
  }

```

```json
    "type": "int",
    "min": 0,
    "max": 2147483647,
    "unit": "s"
  }
}
```

浮点数：

```json
{

  "name": "温度",
  "mode": "r",
  "define": {
    "type": "float",
    "min": -40,
    "max": 125,
    "step": 0.1,
    "unit": "℃"
  }
}
```

字符串：

```json
{
  "id": "firmwareVersion",
  "name": "固件版本",
  "mode": "r",
  "define": {
    "type": "string"
  }
```

## 6. 事件定义

### 6.1 事件字段

| 字段 | 必填 | 类型 | 说明 |
| --- | --- | --- | --- |
| `id` | 是 | string | 事件标识，运行时报文中的 `event_id` |
| `name` | 是 | string | 中文名，1~128 字符 |
| `desc` | 否 | string | 描述，最多 512 字符 |
| `type` | 是 | string | `info`、`alert` 或 `fault` |
| `params` | 否 | array | 事件参数，兼容 `output` |

### 6.2 事件类型

| 值 | 含义 |
| --- | --- |
| `info` | 信息 |
| `alert` | 告警 |
| `fault` | 故障 |

### 6.3 事件参数

| 字段 | 必填 | 说明 |
| --- | --- | --- |
| `id` | 是 | 参数标识 |
| `name` | 是 | 参数名称 |
| `desc` | 否 | 描述 |
| `define` | 是 | 参数数据类型 |

事件参数不允许使用 `struct`。

### 6.4 事件示例

```json
{
  "id": "overTemperature",
  "name": "温度超限",
  "desc": "温度超过告警阈值",
  "type": "alert",
  "params": [
    {
      "id": "temperature",
      "name": "当前温度",
      "define": {
        "type": "float",
        "min": -40,
        "max": 200,
        "unit": "℃"
      }
    },
    {
      "id": "threshold",
      "name": "告警阈值",
      "define": {
        "type": "float",
        "min": -40,
        "max": 200,
        "unit": "℃"
      }
    }
  ]
}
```

运行时事件通常包含：

```json
{
  "events": [
    {
      "event_id": "overTemperature",
      "event_type": "alert",
      "event_ts": 1760000000000,
      "temperature": 92.5,
      "threshold": 85
    }
  ]
}
```

## 7. 行为定义

### 7.1 行为字段

| 字段 | 必填 | 类型 | 说明 |
| --- | --- | --- | --- |
| `id` | 是 | string | 行为标识，运行时映射为 RPC 方法名 |
| `name` | 是 | string | 中文名，1~128 字符 |
| `desc` | 否 | string | 描述，最多 512 字符 |
| `input` | 否 | array | 输入参数，兼容 `inputParams` |
| `output` | 否 | array | 输出参数，兼容 `outputParams` |

### 7.2 行为参数

| 字段 | 必填 | 说明 |
| --- | --- | --- |
| `id` | 是 | 参数标识 |
| `name` | 是 | 参数名称 |
| `desc` | 否 | 描述 |
| `define` | 是 | 参数数据类型 |

参数 `id` 在同一输入或输出列表内唯一。

### 7.3 行为示例

```json
{
  "id": "setMode",
  "name": "设置运行模式",
  "input": [
    {
      "id": "mode",
      "name": "目标模式",
      "define": {
        "type": "int",
        "min": 0,
        "max": 2
      }
    }
  ],
  "output": [
    {
      "id": "success",
      "name": "是否成功",
      "define": {
        "type": "bool"
      }
    }
  ]
}
```

设置继电器：

```json
{
  "id": "setRelay",
  "name": "设置继电器",
  "input": [
    {
      "id": "on",
      "name": "开关状态",
      "define": {
        "type": "bool"
      }
    }
  ],
  "output": [
    {
      "id": "success",
      "name": "是否成功",
      "define": {
        "type": "bool"
      }
    }
  ]
}
```

应用配置：

```json
{
  "id": "applyConfig",
  "name": "应用配置",
  "input": [
    {
      "id": "reportInterval",
      "name": "上报周期",
      "define": {
        "type": "int",
        "min": 5,
        "max": 3600,
        "unit": "s"
      }
    }
  ],
  "output": [
    {
      "id": "success",
      "name": "是否成功",
      "define": {
        "type": "bool"
      }
    }
  ]
}
```

运行时行为映射为 RPC 方法，方法名使用行为 `id`，例如：

```text
setMode
setRelay
applyConfig
```

## 8. 物联网开发平台物模型兼容

平台支持直接导入物联网开发平台导出的物模型文件。导入或保存时，平台会自动识别旧版写法并转换为标准物模型，不需要人工改写。

### 8.1 支持的旧版写法

- 使用 `dataType` 描述数据类型；
- 使用 `stringenum` 表示字符串枚举；
- `min`、`max`、`start`、`step` 使用字符串数字；
- `specs` 或 `fields` 使用数组；
- 结构体字段内使用 `dataType`；
- 字段的 `name`、`desc`、`required` 保留。

### 8.2 转换规则

| 物联网开发平台写法 | 转换后的标准写法 |
| --- | --- |
| `stringenum` | `enum_string` |
| `dataType` | `type` |
| 字符串数值范围 | 数字 |
| `specs` 数组 | `specs` 对象 |
| `fields` | `specs` |
| 结构体字段 `dataType` | 字段 `type` |

### 8.3 兼容示例

物联网开发平台旧写法：

```json
{
  "id": "info",
  "name": "信息",
  "mode": "r",
  "define": {
    "type": "struct",
    "specs": [
      {
        "id": "state",
        "name": "状态",
        "dataType": {
          "type": "stringenum",
          "mapping": {
            "on": "开启",
            "off": "关闭"
          }
        }
      }
    ]
  }
}
```

转换后的标准写法：

```json
{
  "id": "info",
  "name": "信息",
  "mode": "r",
  "define": {
    "type": "struct",
    "specs": {
      "state": {
        "name": "状态",
        "type": "enum_string",
        "mapping": {
          "on": "开启",
          "off": "关闭"
        }
      }
    }
  }
}
```

已经是标准写法的物模型不会被修改。

### 8.4 兼容注意事项

- 转换只处理物模型字段写法，不改变产品 ID、分类 ID、属性名称和事件名称；
- 旧格式中的未知字段会保留在物模型文件中；
- 如果旧格式同时包含 `fields` 和 `specs`，平台会按 `specs` 优先处理；
- 转换后仍需通过平台校验；校验不通过时，请按提示修正字段。

## 9. 校验要求

物模型在导入、保存和更新前会进行校验。校验不通过时，平台会提示具体字段和原因。

### 9.1 必须满足

- `version` 已填写；
- `profile` 已填写，且包含产品 ID；
- `properties` 存在；
- 所有属性、事件、行为、参数都有合法的 `id`；
- 所有属性都有 `name` 和 `mode`；
- 所有属性、事件参数、行为参数都有 `define.type`；
- 数据类型在支持范围内；
- 属性、事件、行为总数不超过 100；
- 属性、事件、行为 `id` 分别唯一；
- 同一事件或行为的参数 `id` 在各自列表内唯一。

### 9.2 数值和范围

- `min` 不能大于 `max`；
- `start` 必须在 `min` 和 `max` 之间；
- `step` 不能为负数；
- `int` 范围不能超过 32 位。

### 9.3 枚举

- `enum` 和 `enum_string` 的映射至少 2 项；
- `enum` 的映射键必须是数字；
- 非枚举类型不建议配置 `mapping`。

### 9.4 结构体

- 结构体字段不能为空；
- 结构体字段不能再次使用 `struct`；
- 事件参数不能使用 `struct`。

### 9.5 事件和行为

- 事件类型只能是 `info`、`alert` 或 `fault`；
- 事件参数和行为参数必须有合法 `id`；
- 参数名称不能为空。

### 9.6 非阻断提示

以下情况通常会提示但不阻止保存：

- 属性使用 `ts`、`event_id`、`event_type`、`event_ts` 作为 `id`；
- 非数值类型配置 `min`、`max`、`start`、`step`；
- 非枚举类型配置 `mapping`；
- 使用保留字段或多余字段。

建议根据提示调整物模型，避免运行时字段冲突。

---

## 10. 运行时字段约定

### 10.1 属性

属性 `id` 同时是遥测键。例如：

```json
{
  "id": "temperature",
  "define": { "type": "float" }
}
```

运行时遥测：

```json
{
  "temperature": 25.6
}
```

### 10.2 事件

事件 `id` 映射为 `event_id`，事件类型映射为 `event_type`，事件参数作为事件字段：

```json
{
  "event_id": "overTemperature",
  "event_type": "alert",
  "event_ts": 1760000000000,
  "temperature": 92.5,
  "threshold": 85
}
```

### 10.3 行为

行为 `id` 作为 RPC 方法名：

```text
setMode
setRelay
applyConfig
```

### 10.4 未知字段

规则链按产品配置处理未知字段：

- 非严格模式：丢弃未知属性，并记录到 `dropped`；
- 严格模式：未知字段可能导致校验失败。

### 10.5 保留字段

以下字段由平台运行时使用，不应作为属性 `id`：

```text
ts
event_id
event_type
event_ts
```

## 11. 提交前检查清单

- [ ] `version` 已填写，长度不超过 32；
- [ ] `profile.ProductId` 或 `profile.productId` 已填写；
- [ ] `properties` 存在，可以是空数组；
- [ ] 所有 `id` 符合 `^[A-Za-z_][A-Za-z0-9_]{0,49}$`；
- [ ] 属性、事件、行为 `id` 分别唯一；
- [ ] 所有属性都有 `mode`，且为 `r` 或 `rw`；
- [ ] 所有属性、事件参数、行为参数都有 `define.type`；
- [ ] `int` 范围在 32 位以内；
- [ ] `min <= max`，`start` 在范围内，`step >= 0`；
- [ ] `enum` 至少 2 项，且键为数字；
- [ ] `enum_string` 至少 2 项；
- [ ] 结构体字段非空，且没有嵌套结构体；
- [ ] 事件类型为 `info`、`alert` 或 `fault`；
- [ ] 属性 + 事件 + 行为总数不超过 100；
- [ ] 没有使用 `ts`、`event_id`、`event_type`、`event_ts` 作为属性 `id`；
- [ ] 从物联网开发平台导入的文件已完成自动转换并通过校验。

## 12. 常见问题

### 12.1 为什么提示缺少 mode？

物模型要求属性必须包含 `mode`。请显式填写 `r` 或 `rw`。

### 12.2 为什么 enum 映射正确但校验失败？

请确认映射写在 `define.mapping` 中。新物模型建议不要在属性级单独配置 `mapping`。

### 12.3 为什么结构体字段不能嵌套？

当前平台只支持一层结构体。结构体字段中出现 `struct` 会校验失败。

### 12.4 为什么事件参数不能用 struct？

事件参数在运行时需要扁平化处理，当前不允许结构体参数。请拆成多个简单类型参数。

### 12.5 为什么 int 范围报错？

`int` 使用 32 位有符号整数范围，超出范围会校验失败。

### 12.6 为什么字符串配置 min/max 只有提示？

`min`、`max`、`start`、`step` 只对数值类型有意义。字符串等类型配置这些字段会收到提示，但通常不会阻止保存。

### 12.7 为什么多余字段没有报错？

当前物模型允许保留多余字段，方便兼容旧文件。多余字段不会参与业务校验。

### 12.8 为什么产品保存后没有生效？

物模型校验通过只代表物模型本身合法。产品保存后还会检查：

- 产品是否已完成产品配置；
- ProductId 是否全系统唯一；
- 平台资源和规则链是否创建成功。

保存失败时保留草稿，并记录处理结果。
