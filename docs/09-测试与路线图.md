## 9.1 设备注册与数据模拟

脚本目录：

```text
tools/src/main/python/simulators/
```

| 脚本 | 用途 |
| --- | --- |
| `register_devices.py` | 按产品配置注册设备，写入服务端属性，导出访问令牌 CSV |
| `setup_gateway.py` | 批量创建网关和子设备，生成网关关系与凭据 CSV |
| `simulate_telemetry.py` | 直连设备遥测、事件、非法数据模拟 |
| `simulate_gateway.py` | 网关代子设备上报 |
| `simulate_gateway_all.py` | 多产品网关和协议连接器模拟 |
| `generate_gateway_config.py` | 生成协议连接器映射和网关配置 |
| `run_protocol_sim.py` | 在 Windows 启动 Modbus、OPC-UA、S7、CAN、ODBC 模拟器 |

规则链校验脚本仍位于 `thing-model/scripts/test_rulechain_validation.js`。

安装依赖：

```powershell
python -m pip install -r tools/src/main/python/simulators/requirements.txt
```

直连模拟：

```powershell
python tools/src/main/python/simulators/simulate_telemetry.py `
  --product-id DEMO_TSL_001 `
  --tsl docs/manuals/examples/standard-thing-model.tsl.json `
  --mode mixed --count 10 --interval 1
```

注册设备：

```powershell
python tools/src/main/python/simulators/register_devices.py `
  --product-id DEMO_TSL_001 `
  --prefix DEMO-ENV --count 10 `
  --site-code SIM `
  --output device-credentials.csv `
  --password tenant
```

网关模拟：

```powershell
python tools/src/main/python/simulators/simulate_gateway.py `
  --gateway-csv gateway-credentials.csv `
  --gateway-name gateway-01 `
  --sub-devices-csv sub-devices.csv `
  --product-id DEMO_TSL_001 `
  --mode mixed --count 2 --interval 1
```

脚本说明见 `tools/src/main/python/simulators/README.md`。CSV 中含明文访问令牌，禁止提交到仓库。

## 9.2 测试

### 单元测试与 Web Slice

```bash
mvn -f thing-model/pom.xml test "-Dtest=!*IntegrationTest"
```

不依赖 Docker 和平台外部服务。

### 数据库集成测试

```bash
mvn -f thing-model/pom.xml test -Dtest=RepositoryIntegrationTest
```

使用 Testcontainers PostgreSQL。

### 平台集成测试

```bash
mvn -f thing-model/pom.xml test -Dtest=ProductRuleChainTbIntegrationTest
```

使用平台测试账号，可通过 `TB_URL`、`TB_USERNAME`、`TB_PASSWORD`、`TB_SYSADMIN_USERNAME`、`TB_SYSADMIN_PASSWORD` 覆盖。该测试需要平台服务和 Docker。

### 全量测试

```bash
mvn -f thing-model/pom.xml test
```

全量测试默认包含平台集成测试。

### 规则链脚本测试

```powershell
node thing-model/scripts/test_rulechain_validation.js
```

覆盖合法遥测、类型错误、越界、int32、报文超限、未知字段、枚举、时间戳、事件和事件数组。

### 前端验证

```bash
cd ui-ngx
yarn lint
yarn build:prod
```

### 视频网关测试

```bash
cd media
uv run pytest
```

## 9.5 数据入湖服务

数据入湖服务负责：

- 消费 `iot.telemetry.normalized` 和 `iot.event.normalized`；
- 按产品创建 TDengine 超级表、按设备创建子表；
- 写入遥测、事件和 DLQ；
- 指标与查询。

产品规则链与数据入湖服务的消息契约见 [04-产品与规则链](04-产品与规则链.md) 的 Kafka 消息章节。

## 9.6 已知限制

- 产品资源准备在 HTTP 请求内完成，没有异步任务和自动补偿。
- 规则链校验使用内嵌 schema，TSL 更新后必须重新发布才能刷新。
- 产品列表没有服务端分页。
- 没有产品弃用和回滚接口，`DEPRECATED` 只是数据库状态值。
- 设备侧业务错误码不由平台直接返回，非法数据通过 `iot.invalid` 排查。
- 平台服务账号初始化依赖平台激活接口和合法邮箱域名。
- 视频网关使用 SQLite，必须单副本运行；页面当前无登录鉴权。
- 当前文档只描述代码中已实现的能力，未实现内容统一放在本文路线图。
