适用场景：产品页面 `/entities/products` 支持多租户。每个厂商租户使用自己的 ThingsBoard 服务账号同步自己的产品；不同租户可以使用相同 ProductId；`SYS_ADMIN` 按租户查看和管理产品。

## 2. 数据模型

新增迁移：

```text
thing-model/src/main/resources/db/migration/V3__tenant_scoped_product.sql
```

目标结构：

```sql
plat_product
  PRIMARY KEY (tenant_id, product_id)

plat_product_tsl
  UNIQUE (tenant_id, product_id, version)
  FOREIGN KEY (tenant_id, product_id)
    REFERENCES plat_product (tenant_id, product_id)

plat_tsl_property
  PRIMARY KEY (tenant_id, product_id, tsl_version, property_key)

plat_tsl_event
  PRIMARY KEY (tenant_id, product_id, tsl_version, event_id)

plat_tsl_action
  PRIMARY KEY (tenant_id, product_id, tsl_version, action_id)

plat_profile_binding
  PRIMARY KEY (tenant_id, product_id, tsl_version)
```

迁移方式：

1. 创建带复合主键的新表。
2. 从旧表复制数据。
3. 子表通过 `product_id + version` 关联 `plat_product_tsl` 回填 `tenant_id`。
4. 删除旧表。
5. 新表重命名回原表名。
6. 重建索引。

新增索引：

```sql
idx_plat_product_tenant
idx_plat_product_tsl_tenant_product
idx_plat_profile_binding_tenant_product
```

## 3. 租户规则

| 角色 | 列表 | 产品详情/编辑/同步 |
| --- | --- | --- |
| `TENANT_ADMIN` | 本租户 | 本租户，tenantId 来自 JWT |
| `SYS_ADMIN` | 全部或指定租户 | 必须显式传 tenantId |
| `CUSTOMER_USER` | 403 | 403 |
| 匿名 | 401 | 401 |

规则：

- `TENANT_ADMIN` 传入其他 tenantId 返回 403。
- `SYS_ADMIN` 产品级接口缺少 tenantId 返回 400 `TENANT_ID_REQUIRED`。
- 跨租户产品详情返回 404，避免泄露产品是否存在。
- 不同租户可以使用相同 ProductId。
- 同租户内同一 TSL 版本内容不同时返回 409 `TSL_VERSION_EXISTS`。

## 4. 后端 API

### 4.1 产品列表

```http
GET /api/products?keyword=xxx&tenantId=<uuid>
```

- `TENANT_ADMIN`：忽略其他 tenantId，始终查询本租户。
- `SYS_ADMIN`：不传 tenantId 查询全部；传入时查询指定租户。

### 4.2 产品级接口

```http
GET  /api/products/{productId}?tenantId=<uuid>
GET  /api/products/{productId}/thing-model?tenantId=<uuid>
PUT  /api/products/{productId}/thing-model?tenantId=<uuid>
GET  /api/products/{productId}/catalog?tenantId=<uuid>
POST /api/products/{productId}/thing-model/validate?tenantId=<uuid>
POST /api/products/{productId}/sync?tenantId=<uuid>
```

`TENANT_ADMIN` 不需要传 tenantId；`SYS_ADMIN` 必须传。

### 4.3 产品创建

```http
POST /api/products
```

请求体中的 `tenantId`：

- `TENANT_ADMIN`：可省略，后端使用 JWT tenantId。
- `SYS_ADMIN`：必须指定。
- `TENANT_ADMIN` 指定其他租户返回 403。

### 4.4 租户服务账号

新增幂等接口：

```http
POST /api/admin/tenants/{tenantId}/provision
```

请求：

```json
{
  "username": "...",
  "password": "...",
  "force": false
}
```

行为：

- 账号不存在：注册。
- 账号已存在且 `force=false`：直接返回 masked account。
- 账号已存在且 `force=true`：更新账号密码。
- 仅 `SYS_ADMIN` 可调用。

保留接口：

```http
POST /api/admin/tenants/{tenantId}/account
GET  /api/admin/tenants/{tenantId}/account
```

## 5. 产品创建与同步流程

```text
POST /api/products
  -> 校验 TSL
  -> TenantAccountService.requireConfigured(tenantId)
  -> 保存 DRAFT
  -> 同步 ThingsBoard
  -> 保存 profileId / assetId / ruleChainId
  -> 状态置 PUBLISHED
```

特点：

- 缺服务账号时直接失败，不保存 DRAFT。
- 同步失败时保留 DRAFT，并写入 `plat_profile_binding.sync_result`。
- 可通过产品详情页“重新同步”按钮重试。
- 每个租户使用自己的 `plat_vendor_account` 登录 ThingsBoard。

同步失败记录：

```text
plat_profile_binding.sync_result = 错误信息
plat_profile_binding.synced_at = 失败时间
```

## 7. 租户生命周期

```text
SYS_ADMIN 创建租户
  -> 租户创建成功
  -> 自动弹出配置厂商服务账号
  -> 没有 TENANT_ADMIN：提示先创建
  -> 有 TENANT_ADMIN：输入凭据并注册
  -> plat_vendor_account 写入
  -> 租户 READY
  -> 创建产品
  -> 产品创建前检查账号
  -> 同步到该租户自己的 ThingsBoard
```

## 8. 安全要求

1. 前端筛选不能替代后端权限校验。
2. `TENANT_ADMIN` 传其他 tenantId 必须 403。
3. 跨租户产品详情返回 404。
4. 不同租户可以使用相同 ProductId；同租户内同一 TSL 版本不能对应不同内容。
5. 服务账号密码必须使用 `THINGMODEL_SECRET_KEY` 加密存储。
6. 不能使用 SYS_ADMIN 账号作为厂商服务账号。
7. 同步失败信息不能包含密码或 JWT。
8. Admin 接口只允许 SYS_ADMIN。

## 9. 已知限制

1. 线上注册接口 500 仍需从部署侧修复，主要是：
   - `THINGMODEL_SECRET_KEY`
   - 数据库 INSERT 权限
   - `created_at` 默认值
   - 数据库/schema 是否一致
2. 自动配置弹窗只在 ui-ngx 创建租户时触发；通过 API 直接创建租户不会自动触发。
3. 当前只注册已有 TENANT_ADMIN，不会自动创建 ThingsBoard 用户。
4. `SYS_ADMIN` 产品级接口必须显式传 tenantId，旧调用方需要调整。
5. Kafka/TDengine 下游租户隔离不在本期范围。
