# 4 产品与规则链

> 中国中铁物联网平台文档集｜[总目录](../README.md)｜上一篇 [物模型与校验](03-物模型与校验.md)｜下一篇 [设备接入](05-设备接入.md)

## 4.1 前置条件

产品发布前，租户必须完成平台初始化，并能正常创建产品配置、资产和规则链。以上资源由平台在产品发布时自动准备，不需要手工注册外部账号。

## 4.2 创建或更新产品

```text
POST /api/products
  -> 校验 JWT，取 JWT 中的 tenantId
  -> 校验请求体 tenantId（如有）不能指向其他租户
  -> 解析并校验 TSL
  -> 检查租户初始化状态
  -> 写 plat_product + plat_product_tsl（DRAFT）
  -> 生成压缩 schema
  -> 生成或更新平台资源
       1. 确保产品规则链
       2. 创建/更新产品配置
       3. 创建/更新产品资产
       4. 写入资产 SERVER_SCOPE 属性
  -> 写 plat_profile_binding
  -> TSL 置为 PUBLISHED
  -> 返回 ProductResponse
```

`PUT /api/products/{productId}/thing-model` 复用同一流程，只使用已有产品的名称、型号和分类，提交新的 TSL 版本。

## 4.3 平台资源

### 产品配置

- 名称：`产品名称 + 空格 + 型号`。型号为空或等于产品名称时只使用产品名称。
- 类型：`DEFAULT`。
- 传输：`DEFAULT`，即平台 MQTT 传输。
- provisioning：`DISABLED`。
- 默认规则链：本次发布的产品规则链。
- 已存在时保留默认规则链、仪表板、队列、镜像、固件、软件等人工配置。

描述包含 产品 ID、CategoryId、TSL 版本和属性/事件/行为数量。

### 产品资产

- 名称：产品 <产品 ID>。
- 类型：`product`。
- 使用平台默认资产模板；未配置默认资产模板时保存失败。
- 写入属性：

```text
product_id
category_id
tsl_version
property_count
event_count
action_count
tsl_json
tsl_schema
strict_unknown
```

### 产品规则链

- 名称直接使用 产品 ID。
- 兼容旧名称 `auto_<ProductId>_telemetry`，首次发布时改名复用。
- 类型为 `CORE`，非根链，绑定到产品配置的 `defaultRuleChainId`。
- 不修改租户根规则链。

## 4.4 规则链拓扑

当前规则链共 14 个节点、14 条连接。

```text
消息类型切换
├─ 上报遥测
│    -> 获取 TSL 属性
│    -> TSL 校验
│    -> 按校验结果分流
│         ├─ 合法   -> 保存时序数据 -> 归一化消息体 -> 按消息类型分流
│         └─ 非法 -> 归一化消息体 -> 按消息类型分流
│                                ├─ 遥测 -> Kafka 遥测
│                                ├─ 事件 -> Kafka 事件
│                                └─ 非法 -> Kafka 非法数据
├─ 上报属性 -> 保存客户端属性
├─ 设备 RPC 请求 -> 记录设备 RPC
├─ 发送到设备的 RPC 请求 -> RPC 调用请求
└─ 其他 -> 记录其他
```

关键行为：

- `TSL Validate` 使用发布时内嵌的压缩 schema。
- 合法遥测先写平台时序库，再归一化并投递 Kafka。
- 非法数据不写平台时序库，只投递 `iot.invalid`。
- 事件和属性都从 `v1/devices/me/telemetry` 进入。
- 不使用平台告警节点。

## 4.5 运行时校验

`telemetry_to_kafka.js` 负责校验和归一化，覆盖：

- 报文必须是 JSON 对象；
- 报文序列化后不超过 4096 字节；
- 属性键名、类型、`required`、`min`/`max`；
- `int` 的 32 位范围；
- `enum` / `enum_string` 的映射；
- `struct` 必须是对象且不嵌套；
- 未知键：严格模式报错，非严格模式丢弃并写入 `dropped`；
- 事件 `event_id` 必须属于 TSL；
- 事件 `event_type` 必须与 TSL 一致；
- 事件参数类型和范围；
- 同一包内 `events[].event_id` 必须一致；
- 秒级时间戳自动乘 1000。

## 4.6 Kafka 消息

配置项：

| 配置 | 默认值 |
| --- | --- |
| `THINGMODEL_KAFKA_BOOTSTRAP` | `kafka-test1:9095,kafka-test2:9095,kafka-test3:9095` |
| `THINGMODEL_TOPIC_TELEMETRY` | `iot.telemetry.normalized` |
| `THINGMODEL_TOPIC_EVENT` | `iot.event.normalized` |
| `THINGMODEL_TOPIC_INVALID` | `iot.invalid` |
| `THINGMODEL_KAFKA_KEY_PATTERN` | `$[deviceName]` |
| `THINGMODEL_RULECHAIN_ENABLED` | `true` |

规则链 Kafka 节点参数：

```text
acks=all
retries=3
batchSize=16384
linger=1
bufferMemory=33554432
```

### 遥测消息

```json
{
  "v": 1,
  "deviceName": "WIFI_DIAG_0001",
  "productId": "9HYN9PJNOY",
  "tslVersion": "1.0",
  "ts": 1758000000000,
  "kind": "telemetry",
  "values": {
    "accX": 0.12,
    "rssi": -62
  },
  "dropped": null,
  "event": null,
  "events": null,
  "invalid": null,
  "siteCode": "S-001"
}
```

`siteCode` 来自设备服务端属性 `ss_site_code`，缺失时不输出。

### 事件消息

单事件使用 `event`：

```json
{
  "v": 1,
  "deviceName": "4DZDCQUA2D-0001",
  "productId": "4DZDCQUA2D",
  "tslVersion": "1.1",
  "ts": 1758000000000,
  "kind": "event",
  "values": null,
  "dropped": null,
  "event": {
    "id": "refuelRecord",
    "type": "info",
    "ts": 1758000000000,
    "data": {
      "volume": 120.5
    }
  },
  "events": null,
  "invalid": null
}
```

事件数组使用 `events`：

```json
{
  "v": 1,
  "deviceName": "4DZDCQUA2D-0001",
  "productId": "4DZDCQUA2D",
  "tslVersion": "1.1",
  "ts": 1758000000000,
  "kind": "event",
  "event": null,
  "events": [
    {
      "id": "alarm",
      "type": "alert",
      "ts": 1758000000000,
      "data": {
        "alarmType": "low_power"
      }
    }
  ],
  "invalid": null
}
```

消息不输出 `level`，由下游按 `type` 映射：`info -> INFO`、`alert -> MAJOR`、`fault -> CRITICAL`。

## 4.7 失败与重试

| 失败点 | 处理 |
| --- | --- |
| 租户初始化不完整 | 创建时返回 `400` / `403` |
| 平台认证失败 | 清除客户端缓存后重试一次 |
| 产品配置、资产或规则链保存失败 | 记录处理结果，接口返回 `502` |
| 保存失败后的 TSL | 保持 DRAFT，可重新保存产品 |
| 同一 TSL 版本内容不同 | 返回 `409 TSL_VERSION_EXISTS` |

产品资源准备在 HTTP 请求内完成，没有异步任务、差异对比、自动补偿或一键回滚。大批量操作需要调用方控制并发。

## 4.8 删除产品

```text
DELETE /api/products/{productId}
  -> 校验产品属于 JWT 租户
  -> 读取该产品所有 TSL 版本的绑定记录
  -> 计算独占的产品配置、资产和规则链
  -> 检查独占产品配置下是否有设备
       有设备 -> 409 PRODUCT_HAS_DEVICES，不删除任何数据
  -> 删除独占的平台资源
       404 视为已删除，其他错误 -> 502 TB_DELETE_FAILED
  -> 删除 plat_product
       -> 外键级联删除 TSL、目录和绑定记录
  -> 204
```

共享资源不出现在 `plat_profile_binding` 独占集合中，不会被删除。平台资源删除失败时数据保留，重试可继续。
