## 8.2 配置项

`thing-model/src/main/resources/application.yml` 支持以下环境变量。

| 变量 | 默认值 | 说明 |
| --- | --- | --- |
| `SPRING_DATASOURCE_URL` | `jdbc:postgresql://localhost:5432/thingmodel` | 数据源 |
| `SPRING_DATASOURCE_USERNAME` | `postgres` | 数据库用户 |
| `SPRING_DATASOURCE_PASSWORD` | `postgres` | 数据库密码 |
| `THINGMODEL_DB_NAME` | `thingmodel` | `DatabaseGuard` 校验的库名 |
| `THINGMODEL_DB_SCHEMA` | 空 | 同库 schema 模式时设置，独立库保持为空 |
| `THINGMODEL_TB_URL` | `http://localhost:18080` | 中国中铁物联网平台地址 |
| `THINGMODEL_SECRET_KEY` | 空 | AES-GCM 密钥，Base64 编码，16/24/32 字节 |
| `THINGMODEL_SERVICE_ACCOUNT_EMAIL_DOMAIN` | `thing-model.local` | 自动创建租户管理员时使用的邮箱域名 |
| `THINGMODEL_KAFKA_BOOTSTRAP` | `kafka-test1:9095,kafka-test2:9095,kafka-test3:9095` | Kafka 地址 |
| `THINGMODEL_TOPIC_TELEMETRY` | `iot.telemetry.normalized` | 遥测 主题 |
| `THINGMODEL_TOPIC_EVENT` | `iot.event.normalized` | 事件 主题 |
| `THINGMODEL_TOPIC_INVALID` | `iot.invalid` | 非法数据 主题 |
| `THINGMODEL_KAFKA_KEY_PATTERN` | `$[deviceName]` | Kafka 消息键 占位符 |
| `THINGMODEL_RULECHAIN_ENABLED` | `true` | 是否生成产品规则链 |
| `THINGMODEL_CORS_ALLOWED_ORIGINS` | `*` | 允许的跨域来源，逗号分隔 |
| `THINGMODEL_CORS_ALLOW_CREDENTIALS` | `false` | 是否允许跨域 Cookie |
| `THINGMODEL_CORS_MAX_AGE` | `3600` | 预检缓存秒数 |

`THINGMODEL_SECRET_KEY` 必须长期固定。更换密钥后，`plat_vendor_account` 中的旧密码无法解密，需要重新初始化租户服务账号。

生产环境建议把 `THINGMODEL_CORS_ALLOWED_ORIGINS` 收紧到实际域名。

## 8.3 初始化数据库

### 独立数据库

```bash
psql -h <db-host> -p 5432 -U postgres -d postgres \
  -v thing_model_password='<password>' \
  -f thing-model/deploy/postgres/init-thingmodel.sql
```

### 同库独立 schema

```bash
psql -h <db-host> -p 5432 -U postgres -d thingsboard \
  -v thing_model_password='<password>' \
  -f thing-model/deploy/postgres/init-thingmodel-schema.sql
```

首次启动 `thing-model` 时 Flyway 自动执行 `V1`、`V2`、`V3`。

V3 会重建产品相关表并复制旧数据，升级前必须备份数据库，并安排维护窗口。

## 8.5 Kubernetes 部署

以下为参考配置，占位符按环境替换。

### Secret

```yaml
apiVersion: v1
kind: Secret
metadata:
  name: thing-model-secret
  namespace: <namespace>
type: Opaque
stringData:
  SPRING_DATASOURCE_USERNAME: thing_model
  SPRING_DATASOURCE_PASSWORD: "<db-password>"
  THINGMODEL_SECRET_KEY: "<base64-32-byte-key>"
```

生产环境使用 SealedSecret、ExternalSecret 或 Vault，不要把明文提交到 Git。

### ConfigMap

```yaml
apiVersion: v1
kind: ConfigMap
metadata:
  name: thing-model-config
  namespace: <namespace>
data:
  SPRING_DATASOURCE_URL: "jdbc:postgresql://<db-host>/thingmodel"
  THINGMODEL_DB_NAME: "thingmodel"
  THINGMODEL_TB_URL: "http://<tb-service>"
  THINGMODEL_KAFKA_BOOTSTRAP: "<kafka-bootstrap>"
  THINGMODEL_TOPIC_TELEMETRY: "iot.telemetry.normalized"
  THINGMODEL_TOPIC_EVENT: "iot.event.normalized"
  THINGMODEL_TOPIC_INVALID: "iot.invalid"
  THINGMODEL_KAFKA_KEY_PATTERN: "$[deviceName]"
  THINGMODEL_RULECHAIN_ENABLED: "true"
  THINGMODEL_SERVICE_ACCOUNT_EMAIL_DOMAIN: "thing-model.local"
```

### Deployment / Service

```yaml
apiVersion: apps/v1
kind: Deployment
metadata:
  name: thing-model
  namespace: <namespace>
spec:
  replicas: 1
  strategy:
    type: Recreate
  selector:
    matchLabels:
      app: thing-model
  template:
    metadata:
      labels:
        app: thing-model
    spec:
      containers:
        - name: thing-model
          image: <registry>/thing-model:<tag>
          imagePullPolicy: IfNotPresent
          ports:
            - containerPort: 8090
          envFrom:
            - configMapRef:
                name: thing-model-config
            - secretRef:
                name: thing-model-secret
          readinessProbe:
            httpGet:
              path: /actuator/health
              port: 8090
            initialDelaySeconds: 20
            periodSeconds: 10
          livenessProbe:
            httpGet:
              path: /actuator/health
              port: 8090
            initialDelaySeconds: 60
            periodSeconds: 20
          resources:
            requests:
              cpu: "200m"
              memory: "512Mi"
            limits:
              cpu: "1"
              memory: "1Gi"
---
apiVersion: v1
kind: Service
metadata:
  name: thing-model
  namespace: <namespace>
spec:
  selector:
    app: thing-model
  ports:
    - name: http
      port: 8090
      targetPort: 8090
```

单副本 + `Recreate` 用于避免多个实例同时执行 Flyway 迁移。扩容前应确认迁移已完成，并评估共享数据库的运行方式。

### AI Agent

完整示例见 `ai-agent/deploy/k8s/ai-agent.yaml`，包含 Secret、ConfigMap、Deployment 和 Service。

```bash
kubectl -n <namespace> apply -f ai-agent/deploy/k8s/ai-agent.yaml
kubectl -n <namespace> rollout status deployment/ai-agent
```

部署前替换 `<namespace>`、`<registry>`、`<tag>`、`<openai-api-key>`。`AI_AGENT_THING_MODEL_URL` 和 `AI_AGENT_THINGSBOARD_URL` 指向集群内实际服务。

AI Agent 监听 `8000`，就绪检查为 `/ready`，存活检查为 `/health`。

### 视频网关

完整示例见 `media/deploy/k8s/media.yaml`，包含 ConfigMap、PersistentVolumeClaim、Deployment、Service 和 Ingress。

```bash
kubectl -n <namespace> apply -f media/deploy/k8s/media.yaml
kubectl -n <namespace> rollout status deployment/media
```

视频网关监听 `4201`，健康检查为 `/health`。它使用 SQLite，必须保持单副本；PVC 挂载到 `/data`，并设置 `MEDIA_DB_PATH=/data/media.db`。

## 8.6 前端网关

```nginx
server {
  listen 80;
  server_name _;
  root /usr/share/nginx/html;
  index index.html;
  client_max_body_size 20m;

  location / {
    try_files $uri $uri/ /index.html;
  }

  location /api/thing-model/ {
    proxy_pass http://thing-model:8090/api/;
    proxy_set_header Host $host;
    proxy_set_header X-Real-IP $remote_addr;
    proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
    proxy_set_header X-Forwarded-Proto $scheme;
  }

  location /api/ai-agent/ {
    proxy_pass http://ai-agent:8000/;
    proxy_set_header Host $host;
    proxy_set_header X-Real-IP $remote_addr;
    proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
    proxy_set_header X-Forwarded-Proto $scheme;
  }

  location /api/ws {
    proxy_pass http://<tb-service>;
    proxy_http_version 1.1;
    proxy_set_header Upgrade $http_upgrade;
    proxy_set_header Connection "upgrade";
    proxy_set_header Host $host;
    proxy_read_timeout 3600s;
    proxy_send_timeout 3600s;
  }

  location /api/ {
    proxy_pass http://<tb-service>;
    proxy_set_header Host $host;
    proxy_set_header X-Real-IP $remote_addr;
    proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
    proxy_set_header X-Forwarded-Proto $scheme;
  }

  location /static/ {
    proxy_pass http://<tb-service>;
  }

  location /oauth2/ {
    proxy_pass http://<tb-service>;
  }

  location /login/oauth2/ {
    proxy_pass http://<tb-service>;
  }
}
```

`/api/thing-model/` 的 `proxy_pass` 末尾必须是 `/api/`，否则路径不会重写。

`crec-ui` 使用 `nginx:1.27-alpine`，把上述配置挂载为 `/etc/nginx/conf.d/default.conf`，Service 暴露 80 端口。Ingress 指向 `crec-ui`，并设置：

```yaml
annotations:
  nginx.ingress.kubernetes.io/proxy-body-size: "20m"
  nginx.ingress.kubernetes.io/proxy-read-timeout: "3600"
  nginx.ingress.kubernetes.io/proxy-send-timeout: "3600"
```

视频网关有两种接入方式：

- 独立子域（推荐）：Ingress 指向 `media:4201`，把部署产物 `assets/media.config.json` 的 `consoleUrl` 设为 `https://media.example.com/cameras`。
- 同域子路径：在网关增加：

  ```nginx
  location /media-console/ {
      proxy_pass http://media:4201/;
  }
  ```

  并以 `MEDIA_ROOT_PATH=/media-console` 启动视频网关。

## 8.7 初始化租户服务账号

自动方式：

```bash
kubectl -n <namespace> port-forward svc/thing-model 8090:8090

curl -X POST "http://localhost:8090/api/admin/tenants/$TENANT_ID/provision-auto?force=false" \
  -H "X-Authorization: Bearer $SYSADMIN_JWT"
```

自动流程：

1. 校验租户存在。
2. 创建专用租户管理员。
3. 获取 activation link。
4. 设置 24 位随机密码并激活。
5. AES-GCM 加密写入 `plat_vendor_account`。
6. 清理中国中铁物联网平台客户端缓存。

服务账号格式：

```text
thing-model-svc-<tenantId>@<THINGMODEL_SERVICE_ACCOUNT_EMAIL_DOMAIN>
```

手动兜底：

```bash
curl -X POST "http://localhost:8090/api/admin/tenants/$TENANT_ID/provision" \
  -H "X-Authorization: Bearer $SYSADMIN_JWT" \
  -H "Content-Type: application/json" \
  -d '{"username":"tenant@thingsboard.org","password":"<password>","force":false}'
```

## 8.8 升级与回滚

```bash
kubectl -n <namespace> set image deployment/thing-model \
  thing-model=<registry>/thing-model:<new-tag>
kubectl -n <namespace> rollout status deployment/thing-model
```

```bash
kubectl -n <namespace> set image deployment/crec-ui \
  crec-ui=<registry>/crec-ui:<new-tag>
kubectl -n <namespace> rollout status deployment/crec-ui
```

回滚镜像：

```bash
kubectl -n <namespace> rollout undo deployment/thing-model
kubectl -n <namespace> rollout undo deployment/crec-ui
```

Flyway 迁移只向前。回滚镜像不等于回滚数据库结构；V3 等重建表的迁移必须依赖升级前备份恢复。

规则链脚本不会因重启服务自动刷新。修改脚本后需要重新保存或发布产品。

## 8.9 验证

```bash
curl http://localhost:8090/actuator/health
kubectl -n <namespace> get pods
kubectl -n <namespace> logs deploy/thing-model --tail=100
```

检查：

- `thing-model` 健康检查返回 `UP`。
- 租户管理员能打开 `/entities/products`。
- 系统管理员菜单没有产品，直接访问会被拦截。
- 产品创建后平台出现产品配置、资产、规则链。
- Kafka 三个 主题 有数据。
- 平台服务账号初始化成功。
- 视频网关 `/health` 返回 `ok`，`/entities/media` 可正常打开。

## 8.10 常见问题

| 现象 | 排查 |
| --- | --- |
| `Failed to decrypt tenant credential` | `THINGMODEL_SECRET_KEY` 与 `plat_vendor_account` 不匹配；恢复旧密钥 或重新初始化账号 |
| `TENANT_ACCOUNT_MISSING` | 当前租户没有服务账号；执行 `provision-auto` |
| 产品发布 `502` | 查看平台资源状态和服务账号权限 |
| `/api/thing-model` 404 | 检查 Ingress、Nginx 路由、`proxy_pass` 末尾 `/api/`、Service 命名空间 |
| 页面刷新 404 | Nginx 缺少 `try_files $uri $uri/ /index.html;` |
| 规则链未更新 | 修改脚本后没有重新保存或发布产品 |
| 平台服务账号创建失败 | 检查邮箱域名、平台初始化接口、数据库写入权限 |
| 服务启动失败 | 检查数据库名/schema、`THINGMODEL_TB_URL`、Kafka 地址、JDK 25 镜像 |
| 私有镜像拉取失败 | 配置 `imagePullSecrets` |
| 视频网关 iframe 空白 | 检查 `media` 4201、`assets/media.config.json`、Ingress 地址 |
| 视频预览黑屏 | 设备未推流或 HLS/WebRTC 地址不可达；先直接访问预览地址 |
| 视频网关混合内容 | HTTPS 页面需使用 HTTPS 的 media 与 HLS/WebRTC |
